This project is Arioso - a machine learning project to synthesize a violin sound from a note input.

The plan for the model is to have a flow matching model from an informed prior mel to a realistic violin-sounding target mel. The informed prior is a sawtooth wave generated from the midi and must be time-aligned to the violin GT audio. The aligning is done by the dataset itself, but needs a manual quality check. We then use BigVGAN-v2 to turn the output mel into an audio.

Project structure: two data **producers** emit **standard dataset roots** (a versioned on-disk layout — `manifest.json` + GT wav + target/prior mels + onsets + optional conditioning tracks) that the model trains on: `DataSynthesizer/` builds the synthetic weak-label set from the score MIDIs, and `Labeler/` is a local web app (`python -m Labeler.server`, port 8765) that transcribes/hand-labels fresh violin recordings and compiles verified clips into a ground-truth root. A top-level `common/` package holds all the shared code the producers and the model agree on — audio I/O, the sample-rate/mel/loudness contracts, the BigVGAN vocoder wrapper, the sawtooth-prior synth, onset alignment, and the dataset-root standard (`common/dataset_schema.py`); reuse it rather than re-implementing (see `common/README.md`). The producers never import each other — only `common/`. `Arioso/` is the flow-matching model + multi-root training/inference code. `Studio/` is the FL Studio–style piano-roll web app (`python -m Studio.server`, port 8766) for composing violin phrases and rendering them offline through Arioso → BigVGAN; see `Studio/README.md`. Vendored third-party repos live under `external/` — the BigVGAN vocoder (`external/BigVGAN`) and the violin-transcription MIDI dataset + MUSC model repo (`external/violin-transcription`).

Vocoder: the model outputs mel-spectrograms that are turned back into audio by **BigVGAN-v2** (`nvidia/bigvgan_v2_44khz_128band_512x`, 44.1 kHz / hop 512 / 128 mel bands). It is vendored under `external/BigVGAN` and wrapped by `common/vocoder.py`; the mel contract it requires (hop, n_fft, win, mel bands, fmin/fmax) is the single source of truth in `common/config.py`. Always compute mels via `common.vocoder.mel_spectrogram` so they match what the vocoder expects.
